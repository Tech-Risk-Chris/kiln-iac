# M3 plan: types, staging, secrecy

**Gate (from [ROADMAP.md](../ROADMAP.md)):** the corpus of known `for_each` and `count` plan-time failures becomes compile errors, including in code paths that do not run.

## What M3 has to buy

Every Kiln program already runs completely at build time, and M2 checks the result against provider schemas. Static types add three things those checks cannot:

1. **Errors in code that no build runs.** A branch taken only for `prod` while you build `dev`, or a helper nobody calls yet.
2. **Secrets.** A sensitive value flowing into a label, a name or a non-sensitive output.
3. **Errors at the definition.** Today an error appears where a value is finally used, which can be far from where it went wrong.

## The decision: sound or gradual

**Decided 17 November 2026: a sound core and a gradual penumbra.** Shapes are gradual; the stage, secrecy and effect lattices are sound.


**Sound inference** (Hindley-Milner with row-polymorphic records, as DESIGN.md says) types every program or rejects it. Idiomatic Kiln code needs a type-system feature or an annotation for each of these:

- vectors of maps whose keys differ (`:spot` on one pool only)
- `(when ...)` inside a map, which makes a field optional
- `merge` of records whose fields are not known (record concatenation)
- `nil` as "absent"

Each feature costs implementation and makes error messages harder to read. Each annotation is friction on code that is not wrong.

**Gradual inference** does the same inference, plus a type `?` that is consistent with every type. Where the checker cannot type something precisely, it yields `?` instead of failing. Errors are reported only for definite clashes. The evaluator and the M2 schema checks stay as the backstop at build time.

**Recommendation:** gradual for the shapes of values, sound for three small lattices carried on every type:

| Lattice | Values | What it decides |
| --- | --- | --- |
| Stage | static ⊑ deferred | what may shape the graph: existence, iteration, names |
| Secrecy | public ⊑ secret | where a value may flow |
| Effect (on functions) | pure ⊑ declares | whether calling it creates resources |

The gate lives entirely in these lattices, and they don't need precise shapes: a value of type `?` still has a known stage and secrecy. This is binding-time analysis from the partial-evaluation literature, which is what Kiln is: a partial evaluator whose residual program is Terraform. Secrecy is ordinary information-flow typing.

## Type language

- **Shapes:** `Nil`, `Bool`, `Num`, `Str`, `Kw`, `Vec τ`, `Tuple τ…`, records `{k: τ, k?: τ | ρ}` with optional fields, `Map τ`, functions `(τ…) -ε-> τ`, `Res "google_x"`, and `?`.
- **Annotations:** every shape carries a stage `s` and a secrecy `p`; every function arrow carries an effect `ε`.
- **Solving:** shapes by unification, with `?` consistent with everything. Annotations by atomic inequalities `a ⊑ b` over variables, solved for the least solution by propagation along a constraint graph. An error is a forced upper bound that is violated, such as `deferred ⊑ static`. The path through the graph is the explanation shown to the user.
- **Polymorphism:** let-generalisation at `def` and `defn`, over shapes and annotations, so a helper like `labels` works on static and deferred inputs alike.

## Where the constraints come from

| Construct | Constraint | Error |
| --- | --- | --- |
| Reading a resource attribute | result is deferred; secret if the schema marks it `sensitive` | |
| Data source attributes, `ref` to another stack | deferred | |
| `str`, arithmetic, comparison, `get`, `tf/*` | result is the join of the arguments | |
| `if` whose branches have effect *declares* | condition is static | K0312 |
| `for`, `map`, `filter`, `reduce` | collection is static | K0313 |
| Logical name of a declaration or component instance | static and public | K0314 |
| Argument the schema does not mark `sensitive` | public | K0320 (new) |
| `output` without `:sensitive true` | public | K0321 (new) |
| `tf/expr` | deferred, `?`, public unless marked `:secret` | |

Today's runtime checks for K0312–K0314 stay as a backstop.

## Pipeline

Per top-level form: **expand → infer → evaluate.** Macros still run on the evaluator during expansion. Because Kiln has no forward references, top-level order is already a valid checking order.

## Steps, each landing green

1. **Dynamic secrecy.** *Done.* Reading a sensitive attribute marks the value secret; the mark survives `str`, functions, conditionals and Terraform function calls, and is checked against the schema at declarations (K0320), outputs (K0321), and `count` / `for_each`. `(tf/nonsensitive x)` declassifies; `(secret x)` marks a deferred value. Reads keep the schema of nested blocks, so `(:client_kye (get (:master_auth c) 0))` is caught too (K0707, K0708).
2. **Self-recursion with a structural check.** *Done.* A `defn` may call itself if one fixed parameter receives a strict part of itself in every recursive call: `(rest xs)`, a destructured part, an element via `for`, `map`, `mapcat` or `filter`, or `(:k x)`. The check is syntactic, at the definition (K0401, K0403). At run time the parameter's structural size must also shrink (K0402), which makes termination a guarantee. Mutual recursion is impossible anyway: there are no forward references.
3. **Expansion-first pipeline and inference of shapes, reporting nothing.** Run it over every test and example; it must type all existing code without a single false positive before it may report.
4. **Annotation lattices and their errors.** K0312–K0314 become static; K0320 and K0321 are new. Explanations follow the constraint path.
5. **Resource constructor types from the schema cache.** Literal argument maps are checked statically; maps built by `merge` fall back to the M2 runtime check.
6. **`count-deferred` and `for-each-deferred`.** These emit real `count` and `for_each`; reads from such a resource become indexed or `one(...)` expressions.
7. **Typed modules.** `kiln schema` also caches module variable declarations; module inputs are checked against them.

`tests/m3.rs` holds the gate corpus: plan-time `count` and `for_each` failures, each placed in a branch that the build does not take.

## Open questions

1. ~~Sound or gradual~~: decided, see above.
2. **Annotation syntax.** The proposal is none in M3 beyond `(tf/expr "..." :as T)` and marking a value secret. The DESIGN.md idea of requiring annotations at `defcomponent` boundaries would wait until error messages show a need for it.
3. **Reads from a `count-deferred` resource:** `one(x[*].attr)`, which is null when absent, or an explicit `(when-exists x ...)` form that keeps absence visible in the types.
